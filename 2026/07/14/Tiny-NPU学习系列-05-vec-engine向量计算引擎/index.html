模块简介

vec_engine 主要用来实现向量逐元素计算，当前支持四种操作：

  • ADD：加法
  • MUL：乘法
  • SCALE_SHIFT：缩放移位
  • CLAMP：截断

另外，这个模块还支持 copy2d_mode。这个模式主要用来做二维拷贝，README 中的用途是把多个 attention head 拼接到 attention buffer 中。例如每个 head 的形状是 [S, 16]，四个 head 最终拼成 [S, 64]。

模块端口

这里比较重要的是三个接口：

  • command interface：上层控制逻辑通过 cmd_valid/cmd_ready 发命令。
  • SRAM read/write ports：vec_engine 自己不存储数据，而是从 SRAM 读操作数，再把结果写回 SRAM。
  • copy2d mode：复用同一套读写 SRAM 流程，只是地址生成方式从一维索引变成二维行列索引。

这个 FSM 的关键是 S_WAIT。因为 SRAM 是同步读，S_READ 周期给出读使能和地址后，数据不会立刻出现在 sram_rd*_data 上，而是要等一个周期。因此模块要在 S_WAIT 接收读数据，然后再进入 S_PROCESS 做计算和写回。

命令寄存器

命令到来时，先把输入参数锁存到内部寄存器中。这样后续状态机执行时，即使外部命令接口变化，也不会影响当前任务。

copy2d 模式

copy2d 模式把 length 解释为列数，把 cmd_m 解释为行数，并用 cmd_K 和 cmd_imm 分别表示源地址行步长与目标地址行步长。

行列计数器如下：

copy2d 和普通向量计算共用同一套 FSM，只是在地址生成和写回数据选择上不同：

  • 普通模式：地址由 base + r_idx 生成，写回 ALU 结果。
  • copy2d 模式：地址由 base + row * stride + col 生成，写回 src0 原始数据。

状态输出

cmd_ready 表示当前可以接收新命令；busy 表示模块正在执行；done 表示本次命令执行完成。

小结

vec_engine 一开始看起来比较复杂，主要是因为它同时包含了普通向量计算和 copy2d 两种模式。理解功能之后，可以按下面几步拆开看：

  • 先看 FSM：IDLE -> READ -> WAIT -> PROCESS -> DONE。
  • 再看 SRAM 地址生成：普通模式用 r_idx，copy2d 模式用 row/col/stride。
  • 然后看 S_WAIT：同步 SRAM 读数据需要打一拍。
  • 最后看 S_PROCESS：普通模式写 ALU 结果，copy2d 模式写原始读出数据。

这样拆开之后，这个模块本质上就是一个由 FSM 控制的 SRAM 读算写小引擎。
