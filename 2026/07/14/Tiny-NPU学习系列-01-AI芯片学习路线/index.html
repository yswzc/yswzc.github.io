总体架构图

0. 学习方法

每看一个模块，都按这个固定问题拆：

  • 这个模块解决什么问题？
  • 输入输出端口有哪些？谁驱动它？它驱动谁？
  • 有没有 FSM？每个状态做什么？
  • 哪些信号打一拍？为什么打一拍？
  • 数据从哪里读？写到哪里？
  • valid/ready/busy/done 的语义是什么？
  • 我能不能给它写一个最小 testbench？
  • 它在完整 NPU 数据流里处于什么位置？

建议 Obsidian 笔记结构：

1. 存储系统 SRAM

目标

理解片上 SRAM 为什么是 AI 芯片最重要的基础模块之一。

重点文件

  • rtl/mem/sram_dp.sv
  • rtl/mem/banked_sram.sv
  • rtl/mem/kv_cache_bank.sv
  • tb/sram_dp_tb.sv

必须搞懂

  • 同步 SRAM 读为什么需要等时钟边沿？
  • write-first 是什么？
  • 双端口 SRAM 为什么可以一边读一边写？
  • banked_sram 里为什么要保存 rd_bank_idx_d？
  • 读请求和读数据如何对齐？
  • 如果写端有 wr_done，为什么通常也要打一拍？

动手任务

  • 写 sram_dp_tb.sv，测试读写、write-first、双端口同周期读写。
  • 写 banked_sram_tb.sv。
  • 画一张 rd_en -> rd_valid -> rd_data 的波形图。
  • 画一张 wr_en -> mem updated -> wr_done 的波形图。

输出笔记

  • sram_dp
  • banked_sram
  • kv_cache_bank

2. 简单算子 Engine

目标

理解一个 AI 算子如何被硬件 FSM 拆成“读 SRAM -> 计算 -> 写 SRAM”。

建议顺序

  1. rtl/ops/vec_engine.sv
  2. rtl/ops/gelu_engine.sv
  3. rtl/ops/layernorm_engine.sv
  4. rtl/ops/softmax_engine.sv

必须搞懂

  • cmd_valid 如何启动 engine？
  • busy 和 done 分别表示什么？
  • SRAM 读数据延迟如何被 FSM 处理？
  • INT8 饱和加法怎么实现？
  • GELU/Softmax 里为什么会用 LUT？
  • LayerNorm 为什么需要 mean/variance/requantize？

推荐仿真

输出笔记

  • vec_engine
  • gelu_engine
  • layernorm_engine
  • softmax_engine
  • 算子Engine通用FSM

3. GEMM 与脉动阵列

目标

理解 AI 芯片核心计算单元：矩阵乘和 systolic array。

重点文件

  • rtl/gemm/mac_int8.sv
  • rtl/gemm/mac_fp16.sv
  • rtl/gemm/pe.sv
  • rtl/gemm/systolic_array.sv
  • rtl/gemm/gemm_ctrl.sv
  • rtl/gemm/gemm_post.sv

必须搞懂

  • INT8 x INT8 -> INT32 accumulator 为什么合理？
  • PE 里有哪些寄存器？
  • A/B 数据如何在阵列里流动？
  • 什么是 weight-stationary？
  • gemm_ctrl 如何从 SRAM 喂数据？
  • gemm_post 为什么要把 INT32 重新量化回 INT8？

推荐练习

  • 手画一个 4x4 systolic array 的数据流。
  • 用一个 2x2 矩阵例子手算输出。
  • 对照仿真波形看 MAC accumulate 的过程。

输出笔记

  • MAC
  • PE
  • systolic_array
  • gemm_ctrl
  • gemm_post

4. DMA 与 AXI

目标

理解外部 DDR 数据如何搬运到片上 SRAM。

重点文件

  • rtl/bus/axi_dma_rd.sv
  • rtl/bus/axi_dma_wr.sv
  • rtl/bus/axi_lite_regs.sv
  • rtl/bus/axi_types.sv

必须搞懂

  • AXI read address channel: ARVALID/ARREADY
  • AXI read data channel: RVALID/RREADY/RLAST
  • AXI write address/data/response 三个通道怎么配合？
  • DMA 为什么要拆 burst？
  • 为什么 AXI burst 不能跨 4KB 边界？
  • cmd_valid/cmd_ready 和 AXI handshake 的关系是什么？

当前项目注意点

  • axi_dma_rd.sv 触发过 Verilator SYNCASYNCNET warning。
  • 当前采用局部 Verilator lint suppress，而不是全局关掉 warning。
  • 如果后续 DMA/reset 行为异常，要优先回顾这里。

输出笔记

  • AXI基础
  • axi_dma_rd
  • axi_dma_wr
  • reset策略

5. 微码控制与调度

目标

理解 NPU 如何用一条条 128-bit microcode 指令调度各个 engine。

重点文件

  • rtl/pkg/isa_pkg.sv
  • rtl/ctrl/ucode_fetch.sv
  • rtl/ctrl/ucode_decode.sv
  • rtl/ctrl/scoreboard.sv
  • rtl/ctrl/barrier.sv
  • rtl/top.sv

必须搞懂

  • 一条 128-bit 指令里有哪些字段？
  • fetch 如何从 ucode SRAM 读指令？
  • decode 如何产生各个 engine 的 command？
  • scoreboard 为什么能防止资源冲突？
  • barrier 的作用是什么？
  • program_end 如何让系统停止？

推荐仿真

输出笔记

  • ISA
  • ucode_fetch
  • ucode_decode
  • scoreboard
  • top数据流

  • python/golden/gpt2_infer_golden.py

GPT-2 Block 数据流

必须搞懂

  • 为什么要 Q/K/V 三组 GEMM？
  • Attention score 的形状是什么？
  • Softmax 输出如何再乘 V？
  • Residual add 为什么需要 SRAM0 和 SRAM1 同时读？
  • Python golden model 如何作为硬件验证参考？

推荐仿真

7. ONNX Graph Mode

目标

理解通用计算图如何编译成 NPU 可执行指令和 tensor descriptor。

重点文件

  • rtl/graph/graph_top.sv
  • rtl/graph/graph_fetch.sv
  • rtl/graph/graph_decode.sv
  • rtl/graph/graph_dispatch.sv
  • rtl/graph/tensor_table.sv
  • python/onnx_compiler/compile.py

必须搞懂

  • ONNX model 如何变成 graph artifacts？
  • tensor descriptor 记录了哪些信息？
  • graph ISA 和 LLM microcode 有什么区别？
  • Graph Mode 如何调度不同算子 engine？
  • scoreboard 如何支持 DMA + GEMM overlap？

推荐仿真

输出笔记

  • ONNX Graph Mode
  • tensor_table
  • graph_dispatch
  • ONNX编译器

8. 每周安排

Week 1: SRAM 与波形

  • 读 sram_dp.sv
  • 跑 tb/sram_dp_tb.sv
  • 写 banked_sram_tb.sv
  • 输出 SRAM读写时序

Week 2: Vec/GELU/LayerNorm

  • 读 vec_engine.sv
  • 读 gelu_engine.sv
  • 读 layernorm_engine.sv
  • 跑 ./engine_sim
  • 输出 算子Engine通用FSM

Week 3: GEMM

  • 读 mac_int8.sv
  • 读 pe.sv
  • 读 systolic_array.sv
  • 读 gemm_ctrl.sv
  • 手画 4x4 systolic 数据流
  • 输出 systolic_array

Week 4: DMA/AXI

  • 学 AXI valid/ready
  • 读 axi_dma_rd.sv
  • 读 axi_dma_wr.sv
  • 画 DMA read burst 时序
  • 输出 axi_dma_rd

Week 5: Microcode 控制

  • 读 isa_pkg.sv
  • 读 ucode_fetch.sv
  • 读 ucode_decode.sv
  • 读 scoreboard.sv
  • 跑 ./npu_sim
  • 输出 ucode_decode

Week 6: GPT-2 Block

  • 读 gpt2_block_top.sv
  • 读 tb_gpt2_block.cpp
  • 读 gpt2_block_ref.py
  • 跑 ./gpt2_block_sim
  • 输出 GPT2 Block

Week 7+: ONNX 与性能

  • 跑 onnx_smoke_sim
  • 读 graph_dispatch.sv
  • 读 compile.py
  • 理解 tensor descriptor
  • 输出 ONNX Graph Mode
